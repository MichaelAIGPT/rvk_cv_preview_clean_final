## 📌 О проекте

**RVK Safety CV** — отечественная масштабируемая программная платформа компьютерного зрения корпоративного уровня, разработанная для непрерывного автоматического контроля соблюдения правил охраны труда, промышленной безопасности и мониторинга ношения средств индивидуальной защиты (СИЗ) на технологических объектах водоснабжения и водоотведения:
- **Цеха механического обезвоживания осадка (ЦМОО)** — центрифуги, декантеры, шнековые прессы;
- **Насосные станции первого и второго подъемов, машинные залы ГНС** — мониторинг вращающихся насосных агрегатов, электродвигателей и высоковольтных шкафов;
- **Осадкоуплотнители, первичные и вторичные радиальные отстойники** — открытые водные поверхности и опасные перепады высот;
- **Транспортные галереи кека и конвейерные линии** — зоны повышенной травмоопасности движущихся лент;
- **Гаражи спецтехники и боксы аварийно-восстановительных машин (АВМ)** — контроль зон маневрирования автотранспорта.

Система функционирует в режиме 24/7, обрабатывает RTSP-видеопотоки высокого разрешения (Full HD / 4K), непрерывно сопровождает персонал трекером с постоянным ID, осуществляет анатомический контроль СИЗ, фиксирует опасные ситуации и формирует реестр инцидентов с карточками расследования по стандарту **CAPA / 5 Почему (5 Whys)**.

## 📜 История версий платформы

- **v1.0 (Baseline)** — Базовая одностадийная сеть (YOLOv8n Single-Stage) из первичного технического задания подрядчика.
- **v2.0 (Dual-Head)** — Первичный прототип каскадной схемы: отделение силуэтов людей и классификация СИЗ по верхней половине рамки тела.
- **v3.0 (Pose Cascade)** — Внедрение нейросети оценки поз (Human Pose Estimation) с 17 ключевыми точками скелета для надежной анатомической локализации головы и плеч независимо от наклона тела.
- **v3.1 (MLOps & UI)** — Интеграция контура активного обучения: экспресс-разметчик FastTagger, банк кропов, векторный редактор опасных зон и карточки CAPA (5 Почему).
- **v3.2** — Обучение на 341 верифицированном образце и фиксация контрольного прогона `RUN-002` (точность 87.8%).
- **v3.3 (Текущая версия)** — Завершение 15 эпох глубокого дообучения весов на GPU RTX 4070 с внедрением базы Hard Negatives (подавление ложных тревог оборудования в кадрах 623–633), модуль трекера прогонов (`Run Progression Tracker`), двухоконный плеер сравнительного анализа и расчет масштабирования серверов.

## 🧠 Стек нейросетевых моделей платформы (AI Lab Reference)

В платформе используется согласованный ансамбль специализированных нейросетевых моделей:

1. **Детектор силуэтов (YOLOv8 Detection):**
   - *Роль в конвейере:* Обнаружение людей в панорамном кадре технологического цеха, отсечение фонового шума и передача координат в трекер.
   - *Обучение:* Предобучен на 1.5+ млн изображений людей, устойчив к сложному ракурсу камер наблюдения.
2. **Модуль скелетной анатомии (YOLOv8-Pose):**
   - *Роль в конвейере:* Определение 17 ключевых точек анатомического скелета (нос, глаза, уши, плечевой пояс, локти, таз).
   - *Назначение:* Точнейшая пространственная вырезка области головы и плеч для анализа СИЗ даже в нестандартных позах (наклоны над насосом, приседания, подъем по лестнице).
3. **Специализированный классификатор СИЗ (EfficientNet-B0):**
   - *Роль в конвейере:* Анализ вырезанного анатомического фрагмента головы на наличие каски и правильность ношения, а также проверка сигнального жилета.
   - *Дообучение:* Модель очищена и дообучена на выборке цеха с добавлением Hard Negatives (округлые металлические детали оборудования, фланцы, манометры).
4. **Легковесный классификатор (MobileNetV3 Edge):**
   - *Роль в конвейере:* Альтернативный энергоэффективный классификатор для периферийных серверов без дискретных видеокарт (инференс на CPU через OpenVINO за 8.2 мс).
5. **Модуль попиксельной сегментации (YOLOv8-Seg) *(в процессе тестирования)*:**
   - *Роль в конвейере:* Построение точной полигональной маски контура человека для разделения близко стоящих рабочих и отсечения сложного промышленного фона.
6. **Мультиобъектный трекер (ByteTrack):**
   - *Роль в конвейере:* Сопоставление силуэтов между кадрами и удержание стабильного идентификатора (`Track ID`). Позволяет накапливать историю статуса рабочего и обеспечивает кулдаун инцидентов.

## 🖥️ Функциональные возможности интерфейса

### 1. Операционный диспетчерский центр (Operations Console)
- **Видеопоток реального времени:** MJPEG-стриминг со сверхнизкой задержкой и динамическим наложением векторной графики детекций (HUD);
- **Управление просмотром:**
  - Плавный цифровой зум колесиком мыши (от 50% до 300%) с режимом перемещения по кадру (Pan / Drag);
  - Полноэкранный режим с фокусом на камере («⛶ На весь экран»);
  - Покадровая навигация вперед и назад (⏮️ / ⏭️) для разбора спорных моментов;
  - Регулировка скорости воспроизведения (0.5x, 1x, 2x, 4x);
- **Мультикамерный мониторинг:** Переключение между технологическими постами (Камеры 1–5) с живыми превью-каналами.

### 2. Панель оперативного управления модулями ТБ
Независимые тумблеры на панели инструментов позволяют оператору включать и выключать требуемые детекторы:
- `⛑️ Каски` — контроль наличия защитных касок на голове персонала;
- `🦺 Жилеты` — контроль ношения сигнальной спецодежды со световозвращающими полосами;
- `🚬 Курение` — обнаружение открытого тления и жеста поднесения руки ко рту *(в процессе тестирования)*;
- `📱 Смартфон` — контроль использования мобильных устройств водителями спецтехники и персоналом вблизи движущихся механизмов *(в процессе экспериментального тестирования)*;
- `⚠️ Опасные зоны` — подсветка полигонов оборудования и контроль опасного сближения *(в процессе тестирования)*;
- `🧩 Маска силуэта` — попиксельная сегментация тела человека (YOLOv8-Seg) *(в процессе тестирования)*;
- `🔥 Пожар и задымление` — детектор признаков возгорания *(в процессе тестирования)*.

### 3. Интерактивный редактор опасных технологических зон *(в процессе тестирования)*
- Инструмент векторного рисования полигональных зон произвольной формы прямо по живому видеокадру;
- Классификация зон по степени риска: *«Критическая опасность»*, *«Зона насосных агрегатов»*, *«Зона электроустановок»*;
- Индивидуальная настройка допустимого времени нахождения (Dwell Time Threshold) и обязательных требований СИЗ.

### 4. Юридический журнал инцидентов и модуль CAPA (5 Почему)
- **Фильтрация информационного шума:**
  - *Фильтр дребезга (Debounce 3+ кадра):* кратковременные смазывания или повороты головы отфильтровываются;
  - *Кулдаун дедупликации (15–30 секунд):* непрерывное нахождение нарушителя в кадре создает ровно одну карточку события с привязкой к его треку;
- **Двухэтапная верификация оператором:** маркировка карточки статусами *«Подтверждено»* или *«Ложное срабатывание»*;
- **Мгновенный переход:** кнопка **`▶ В плеер`** осуществляет точный покадровый переход видеоплеера непосредственно к моменту фиксации нарушения;
- **Карточка расследования CAPA (Corrective and Preventive Action):**
  - Структурированный разбор инцидента по методике **«5 Почему» (5 Whys)** для выявления коренной причины (Root Cause);
  - Назначение корректирующих мероприятий, ответственного лица и контрольного срока устранения;
- **Экспорт отчетности в один клик:**
  - **Excel (.xlsx)** — официальный отчет для инспекции по охране труда;
  - **CSV** — структурированный массив для импорта в корпоративную систему 1C:ERP / ТОиР;
  - **SCADA Telemetry (OPC UA)** — передача сигналов тревог в АСУ ТП цеха.

### 5. AI Лаборатория и контур активного обучения (Active Learning MLOps)
- **Банк кропов (`/dataset`):** Каталог вырезок силуэтов и голов с фильтрацией и сортировкой;
- **Экспресс-разметчик FastTagger (`/tagger`):** Эргономичный веб-интерфейс верификации с поддержкой горячих клавиш (`1` — Каска, `2` — Без каски, `3` — Ложное/Оборудование);
- **Модуль фонового дообучения:** Запуск обучения модели на накопленных образцах предприятия в один клик прямо из браузера (с автоматическим сохранением лучших весов `best.pt`);
- **Центр переключения моделей:** Мгновенная смена весов в конвейере без остановки сервера (SOTA V3, MobileNetV3 Edge для CPU, Baseline подрядчика);
- **Экспорт датасета:** Выгрузка верифицированных сэмплов в стандартный формат YOLO / PyTorch для дальнейших исследований.

### 6. Модуль бенчмаркинга и трекер прогресса (Run Progression Tracker)
- Фиксация результатов каждого контрольного прогона (`RUN-001`, `RUN-002`, `RUN-003`, ...);
- Автоматический расчет метрик: точность (Precision), полнота (Recall), F1-мера, количество ложных тревог;
- Наглядная таблица динамики улучшения: отображение дельты прироста точности к базовой модели подрядчика и к предыдущей итерации нашей системы.

### 7. Двухоконный A/B плеер сравнительного анализа
- Синхронное покадровое сопоставление работы моделей «бок о бок»: слева — базовая одностадийная сеть подрядчика (порт 18080), справа — трехстадийный каскад SOTA v3.3 (порт 8000).

### 8. Аналитический дашборд руководителя (Executive Safety Dashboard)
- Сводная инфографика и ключевые показатели эффективности (KPI) охраны труда;
- Распределение нарушений по сменам, дням недели и цехам;
- Тепловая карта распределения опасных инцидентов по зонам предприятия;
- Индекс безопасности технологического объекта (Safety Score).

### 9. Инженерная панель и системная диагностика
- Конфигурация порогов уверенности (Confidence thresholds), порога перекрытия NMS IoU, параметров трекера ByteTrack (длина трека, max age);
- Выбор вычислительного бэкенда (NVIDIA CUDA / TensorRT / OpenVINO / CPU) и управление числом потоков;
- Диагностический аудит-лог с возможностью скачивания архива системных журналов.

## ⚙️ Системные требования и расчет пропускной способности серверов (Sizing & Capacity)

### Оптимизация нагрузки в каскаде v3.3
Для обеспечения масштабируемости на большом числе видеокамер в платформе реализован алгоритм **адаптивного опроса классификатора**:
1. Детектор людей (YOLOv8) обрабатывает кадры видеопотока с оптимальной частотой **10–12 FPS** (скорость передвижения персонала на объектах водоканала составляет 1–1.5 м/с, поэтому 10 кадров в секунду обеспечивают 100% покрытие без пропусков).
2. Трекер (ByteTrack) непрерывно удерживает траекторию человека.
3. Тяжелый классификатор EfficientNet вызывается не на каждом кадре для каждого человека, а **при первичном захвате трека и далее с периодичностью 2 раза в секунду** для подтверждения статуса СИЗ.
4. Это архитектурное решение снижает общую вычислительную нагрузку на 75–80%, позволяя подключать значительно больше камер на один сервер.

Скрипт автоматически подготовит виртуальное окружение `.venv`, проверит зависимости и запустит платформу.

### Ручной запуск (Windows / Linux)

1. **Клонируйте репозиторий:**
   ```bash
   git clone -b feature/rvk-safety-cv-v3.3 https://github.com/AIUniverstorage/rvk-safety-cv.git
   cd rvk-safety-cv
   ```

2. **Создайте и активируйте виртуальное окружение Python (рекомендуется Python 3.10 или 3.11):**
   - *Windows:*
     ```cmd
     python -m venv .venv
     .venv\Scripts\activate
     ```
   - *Linux:*
     ```bash
     python3 -m venv .venv
     source .venv/bin/activate
     ```

3. **Установите зависимости:**
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. **Запустите сервер платформы:**
   ```bash
   python backend/app.py
   ```

5. **Откройте веб-интерфейс в браузере:**
   ```
   http://localhost:8000/
   ```
   *(Интерактивная спецификация REST API Swagger доступна по адресу `http://localhost:8000/docs`)*
